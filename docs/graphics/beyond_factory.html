THE LOOKOUT — Beyond Factory

From a stock OpenWrt travel router to a live mapping appliance — the complete account, beginning to end.

This is the whole story in one page: what a stock GL‑MT6000 is out of the box, exactly what The Lookout adds to teach it to read a radio, serve a map and stream audio, how it all goes on, and what it costs — measured on a carton‑fresh box in a single setup pass. Every addition rides a supported channel: the vendor’s own signed package feed and a handful of plain‑Python files. No firmware rebuild, no custom kernel, nothing forced.

0   The starting point a stock box, before anything is added

The router ships as a capable OpenWrt device — OpenWrt 21.02 on a MediaTek MT7986 (aarch64), ~1 GB RAM, a 7.2 GB writable overlay, GL firmware v4.11.0 / kernel 5.4.238. But out of the box it knows nothing of radios, maps or audio: no Python, no sound driver, no map server. Measured stock, it uses about 427 MB of its 7.2 GB overlay and listens only on its own admin pages, DNS and SSH (22 / 53 / 80 / 443, plus a localhost‑only GL API on 3008). Everything below is what turns that into the appliance.

1   Driver packages installed with opkg, from the vendor’s own signed, kernel‑matched feed

kmod-usb-audio
The USB audio driver. Lets the router see the USB sound card as a recording device so it can hear the radio. Pulled from GL’s feed for the exact running kernel (5.4.238) — no generic kmod, no vermagic mismatch.
kmod-sound-core
Core sound support that the audio driver sits on. Pulled in automatically with it.
The driver that reads the radio’s GPS link (USB networking / RNDIS) was already built into the router — nothing to add there. Only audio needed a driver. That is OpenWrt’s doing, not ours.

2   Support packages the tools our programs lean on, also via opkg

python3
The Python 3 runtime and standard library. Every Lookout program runs on it. The stock firmware carries no Python — this is what makes the box programmable.
libusb-1.0-0
User‑space USB access. Lets us talk to the Garmin GPS puck directly, in plain code, with no special kernel driver.
alsa-utils (+ alsa-lib)
The standard Linux sound toolkit. Gives us arecord, which captures the radio audio off the sound card.

3   Programs we wrote plain Python, standard library only — small, single‑purpose

bk_bridge.py
Reads the radio’s received GPS over the USB link and re‑serves it as a clean position feed on the network. Also folds in the box’s own GPS as the “you are here” unit.
gps_source.py
Picks where the box’s own position comes from — tries the Garmin first, then other sources — so the right one just works.
garmin_linux.py
Speaks the Garmin’s binary GPS language over USB, in pure Python. Discovers the device’s own data path instead of guessing it.
units_kml.py
The map server. Hands out the browser map, the live units, and the map tiles off the SSD, and lets you rename units on the fly.
lookout_audio.py
Captures the radio audio and streams it to the browser as raw sound — no codec, almost no CPU. Runs on its own, so audio can never disturb the map.
map.html
The map itself, as seen in any browser — the moving units, the Maps menu, and the “Listen” button. Loads the map library below (served from the same box), so it needs no internet.

4   Boot services what turns the programs into a plug‑in appliance

bk-bridge
Starts the position bridge at boot, brings up the radio link, and hands the Garmin to our code.
units-kml
Starts the map server at boot.
lookout-audio
Starts the audio streamer at boot.
hotplug / usb0
Re‑connects the radio link if the radio is plugged in after the box is already running.
All three services restart themselves if they ever stop, and everything comes back on its own after a power‑cycle — pull the plug, plug it back in, the map returns with nobody at a keyboard.

5   Bundled library carried with the box, not installed by opkg

leaflet.js
leaflet.css
Leaflet, the open‑source map library that draws the slippy map in the browser. It ships as two plain files served by the map server alongside map.html — carried with the box, no CDN, no internet — so the map works fully offline.

6   Small data files what the box keeps

aliases.json
The friendly names — turns a raw radio ID into a crew name on the map.
admin_token.txt
A simple key that guards the rename feature.
track_….csv
A daily log of where units went, written automatically.

7   How it all goes on one setup pass, once, with the box briefly online

In order, every step through a supported door:
opkg
Installs the driver and support packages (section 1–2) from GL’s own signed, kernel‑matched feed — the same feed the router updates itself from.
fetch
Downloads the programs, boot services, map page and map library (section 3–5) from the project’s public repository.
enable + start
Registers the three services to launch at boot and starts them — standard OpenWrt procd init.
sync
Commits everything to flash so it survives a power‑cycle.
For the owner this is one button in a small Windows helper (Lookout Manager) that runs the sequence over SSH — a few minutes, once. After it, the box never needs the internet again and can be frozen on fixed firmware.
8   The measured result — proven from a bare box
  • On 2026‑11‑18 a carton‑fresh GL‑MT6000 (first‑booted, firmware updated to current GL, nothing else) was provisioned in a single pass: Python installed from scratch, the USB‑audio driver pulled from GL’s kernel‑matched feed, every program, service and the map front‑end in place.
  • Result, from one button: a live Z20 map in the browser, two units moving (“you are here” plus a field radio), and radio audio playing — the whole stack, on a factory box.
  • Cost to the box: about 23 MB of its 7.2 GB storage (measured stock 427 MB → 450 MB) and three application ports added on top of the stock router: 8080 (map), 8081 (audio), 10110 (position feed).
  • It survives a power‑cycle on its own — pull the plug, plug it back, the map returns with nobody at a keyboard.
A stock router became a working mapping appliance for ~23 MB and three ports — every piece through a supported door.
This is what the platform already makes possible.
The USB‑net driver was built into OpenWrt; the audio driver came straight from GL’s own feed. The Lookout simply assembles what OpenWrt and GL.iNet already provide — drivers and tools from the vendor’s signed feed, programs in plain Python, one open‑source map library carried along. No firmware rebuild, no custom kernel, nothing hacked — each piece doing exactly what it was built to do.
